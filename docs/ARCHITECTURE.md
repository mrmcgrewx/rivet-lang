# Architecture and decisions

Current architecture, 2026-10-25. Native compilation is core to completion. The original interpreter-only implementation was useful groundwork but did not satisfy the intended experiment.

## Binary representation

Canonical source is `.rvb` binary files with a fixed versioned header, numeric opcodes/result tags and length-delimited payloads. RVB1 uses positional single-assignment registers and a console/HTTP entry; RVB2 uses explicitly declared mutable registers and a compute entry. There are no textual names/opcodes or embedded JSON documents. The user explicitly requires binary authorship; the earlier JSON-source rationale is superseded. `BINARY-FORMAT.md` and `COMPUTE-FORMAT.md` specify the bytes; `BINARY-PLAN.md` and `TWO-SUM-PLAN.md` record implementation contracts.

The instruction stream represents a typed acyclic dataflow graph. Fixed numeric references make dependencies explicit; lengths give decoders/editors record boundaries. Canonical object key order and exact EOF remove ambiguous encodings. All instructions preserve ordered failure semantics, even unused values. Compact source is observable; improved model reliability or token efficiency remains unmeasured. Binary does not imply encryption: literal strings can remain visible and a decoder makes structure readable.

The acyclic description applies to RVB1. RVB2 represents a typed control-flow graph: destinations and branch targets are explicit numeric indices, with deterministic instruction order and mutable locals. This supports loops while retaining byte-addressable edits and type checks. A forward must-analysis verifies definite assignment by intersecting definitions over reachable predecessors until a fixed point; instruction zero always has an empty initial incoming state. Structural/type validity is required even for unreachable records. Reachable fallthrough outside the stream is rejected. This is a conventional compiler analysis, not an AI-specific optimization.

`src/language/binary.rs` bounds and validates bytes and constructs private typed IR directly. It never calls the JSON parser. `compile_binary` is the CLI/workbench input path; `inspect_binary` provides disassembly, record/payload offsets, literal metadata and entry location. `encode_binary` supports deterministic roundtrip tests; it is not a required source-authoring step. Examples are committed binary bytes, directly reproducible with `scripts/write_binary_examples.py`. Legacy JSON is isolated to test fixtures and the retained library parser.

## Native compilation

`src/language/binary.rs` decodes binary source to a private typed indexed IR; `src/language.rs` provides execution semantics and a reference interpreter. `src/language/native_codegen.rs` emits LLVM directly from this IR, without running the interpreter. Scalar values become LLVM constants/values; checked addition uses `llvm.sadd.with.overflow.i64` with explicit error branches. Text, conversion, and object operations become direct calls to the C ABI in `native/runtime.h`. HTTP entries emit their own route registration, status, body, and port before calling the transport loop.

Version dispatch sends RVB2 bytes to `src/language/compute.rs`, which owns the separate computation IR, validation and input-aware reference executor. `compute_codegen.rs` lowers each instruction to a native basic block. Typed register slots and array-construction scratch storage are allocated once in function entry; direct loads/stores, checked add/sub intrinsics, signed comparisons and branches implement the program. Generic C calls provide array/map storage, stdin, output and bounds. There is no Two Sum-specific runtime function. The 21-record binary example contains its own scan, complement calculation, lookup decision, insertion and result construction.

The additive linked-list extension adds tag 7 (`IntList`), nullable immutable nodes, typed copies, guarded division/remainder and assertions. Nil/is-nil/copy lower to native null/comparison/load/store operations. Division and remainder branch around zero and signed MIN/-1 before sdiv/srem; assertions generate PC-specific diagnostic blocks. Generic runtime functions expose node allocation/head/next/length and input/output. The 70-record Add Two Numbers source owns both list traversals, digit validation, carry arithmetic, result construction and reversal. No linked-list helper understands decimal addition. `ADD-TWO-NUMBERS-PLAN.md` records the exact contract.

The Float extension adds finite IEEE-754 binary64 registers, exact-bit constants, explicit signed integer conversion, addition/division and scalar return. LLVM emits sitofp/fadd/fdiv with zero-divisor and nonfinite-result guards; no fast-math is enabled. C only formats the scalar and finishes input. The 81-record median program owns binary partition search and its mean computation. `MEDIAN-PLAN.md` defines this additive contract and the separate benchmark-only harness; production runtime has no median helper or benchmark timing hooks.

`src/native.rs` embeds the C support sources, writes LLVM and temporary support files, invokes Clang for object/assembly generation and linking, and publishes an executable plus LLVM, assembly, and metadata sidecars. Backend processes have time/output bounds. Existing destinations are rejected. The established LLVM/Clang backend handles optimization, register allocation, and machine-code generation; writing our own emitter is not part of this milestone.

The verified target is arm64 Mach-O on macOS. Executables link native support and use only system libraries. They do not contain the Rust interpreter, a source parser, an instruction dispatcher, or a dependency on source/sidecar files. Compiler-side Rust dependencies do not become executable runtime dependencies. C support is embedded in the compiler, so builds also work outside the source checkout.

## Runtime boundary and memory

Generated code owns program operations and entry configuration. C helpers own immutable byte values, concatenation, number/boolean formatting, exact JSON encoding, stdout, allocation cleanup, and HTTP sockets/protocol handling. Strings use byte lengths and preserve embedded NUL and UTF-8. Integers remain exact across the signed 64-bit range. Object keys use deterministic ordering. Helpers enforce computed-value/output bounds before unbounded growth.

Values have process lifetime during bounded straight-line computation and are freed on normal exit. Server responses are computed once at startup; no new language values are evaluated per request. C transport handles loopback binding, exact paths/query stripping, 404/405, framing/size/deadline checks, SIGINT/SIGTERM, and clean socket release. `RIVET_CONTROL=1` enables parent-only request-count messages on stderr. Without it, standalone serving needs no parent protocol.

RVB2 values also have process lifetime, with a cumulative 64 MiB logical allocation budget. Arrays charge eight bytes per element; each fixed 32,768-slot map charges 786,432 bytes and allows 10,000 unique keys. Integer maps use unsigned hashing and bounded linear probing; occupied entries grow with the algorithm's data, while allocated capacity is fixed. Each executed instruction consumes one fuel unit, with one million allowed steps. Arrays have at most 10,000 elements; input/output are at most 256 KiB. The reference executor enforces the same semantic bounds. Logical charging bounds program allocations rather than promising a precise process RSS ceiling.

The native fuel optimization exposes the existing check/increment body to LLVM as an `available_externally`/`alwaysinline` definition. Generated source-instruction call sites stay intact; the backend can inline and simplify their machine instructions while preserving the counter and failure order. The additive ABI getter `rv2_fuel_counter` returns the stable address of the same counter used by the unchanged C fallback and reset by cleanup. It performs no memory access or failure, permitting a truthful `memory(none) nounwind willreturn` declaration. No counter manipulation is exposed to Rivet source. Arithmetic, indexing, input and allocation checks remain in place. See `NATIVE-OPTIMIZATION-PLAN.md` for the precise preservation contract.

Each new linked node charges 24 logical bytes and stores its i64, tail and cached length; chains are limited to 10,000 nodes. Native tails are actual pointers to tracked tagged allocations. Reference tails are nullable indices in a flat arena; neither cleanup path recursively drops the chain. Lists may share immutable tails, and copying handles charges no new nodes. Generic list input first validates/charges the count, parses bounded temporary values, then publishes the immutable chain in input order. This preserves input failure ordering across reference/native paths without exposing mutable links. Existing compute ABI 2 is extended with new symbols while prior signatures remain unchanged.

The older Rust HTTP adapter and interpreter server remain for the workbench API and reference tests. An earlier `tiny_http` adapter was replaced after review demonstrated shutdown blocking on incomplete request bodies; owned sockets now have bounded parsing and cancellation. Native transport independently implements the same documented small HTTP subset. Neither adapter is a production HTTP server.

## Workbench and lifecycle

The embedded HTML/CSS/JS UI stores source as Uint8Array bytes, imports/exports `.rvb` files, displays decoded instructions and an editable hex view, and edits literal/port payloads directly. It inspects diagnostics/typed IR/LLVM/assembly and exposes executable metadata/download. Raw octet-stream Build and Inspect requests carry exact program bytes; JSON remains only a control/inspection response protocol and application output format. Build succeeds only after native linking. Persistent files live under `.rivet/builds/<session>/<id>/`; in-memory build state is separate from source edits and from an already running process.

`src/native_process.rs` launches artifact paths as OS children, captures bounded output/exit status, and manages a server by its readiness line and owned PID. Stop sends SIGTERM, waits, then escalates on a bounded timeout and reaps the child. Status detects unexpected exit. Workbench SIGINT/SIGTERM stops its child; artifacts remain usable independently. The UI request inspector makes actual TCP requests. No example output is hardcoded into the workbench.

Compute Run supplies a separate bounded stdin string to that same executable. A writer thread closes stdin after delivery while independent readers drain output and the parent enforces a five-second deadline; a full pipe cannot block timeout handling. The GUI keeps runtime input separate from source/build revisions, so one build handles many inputs. CLI run/interpret read bounded stdin only for compute entries. The workbench run envelope allows worst-case JSON escaping of the full 256 KiB input; decoded input retains its own cap. RVB1 services keep their original transport limits.

## Dependencies and efficiency

Rust 1.90.0, Cargo.lock, and package-lock.json pin build/test dependencies. serde/serde_json handle control messages, reference JSON values and legacy test input; httparse parses workbench/reference HTTP; ctrlc with termination support handles SIGINT/SIGTERM/SIGHUP; libc supports native-process signals. Native production support is C11 plus system libraries. The frontend has no runtime framework; Playwright is test-only.

The initial performance objective is executable file bytes. Compare identical emitted LLVM and C support under baseline `-O0` and size `-Oz` with linker dead stripping. Record actual size plus compilation wall time, preserve semantics under both profiles, and report ties/regressions. This evaluates a conventional backend policy, not a novel optimizer or universal performance claim. Earlier results in `NATIVE-BENCHMARK.json` and `NATIVE-VALIDATION.md` used JSON input and remain historical. The benchmark now consumes `.rvb` examples; current acceptance is `BINARY-VALIDATION.md`. The old Rust interpreter benchmark remains historical reference work.

The `speed` profile adds -O3 and linker dead stripping without weakening checks; size remains the default. The user's broader objective is an agent-oriented language competitive with established languages. `ROADMAP.md` separates future capabilities (functions/modules/libraries, practical IO and authoring tools) from measurements of throughput, latency, memory and agent authoring reliability. The median comparison measures process latency/RSS and preloaded partition search separately against C and Python; its benchmark-only boundary substitutions preserve generated arithmetic and runtime checks. See `MEDIAN-BENCHMARK-METHOD.md`. Binary encoding by itself does not establish faster execution.
